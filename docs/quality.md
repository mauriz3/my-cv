# Quality: tests, coverage, accessibility, and Lighthouse

All three run on every PR and every push to master; axe and Lighthouse use the site produced by `verify` (`site` artifact, no second build), served locally with `scripts/serve-static.mjs`. That server mimics Netlify where it matters (`/path` → `path.html` or `path/index.html`, 404 with `404.html` and `_headers`, CSP included, so a broken CSP is also detected), compresses text with Brotli like Netlify (without that, Lighthouse would measure 6–8× more HTML and CSS bytes than in production), and answers `/geo` with the real Edge Function (`netlify/edge-functions/geo.ts`) and a simulated country (`GEO_COUNTRY`, default `ES`: the notice appears, as for an EU visit). It does not send `X-Robots-Tag`: non-production builds add it on purpose and Lighthouse would count that as an SEO failure (the production artifact does not include it; `deploy-production` checks that).

- **Accessibility (job `a11y`)**: `tests/a11y/axe.spec.ts` (`@axe-core/playwright`, WCAG 2.2 A/AA and best-practice rules) on `/en/`, `/es/`, `/en/visits`, and `/en/privacy` in dark and light theme (`localStorage["nuxt-color-mode"]`), with animations off (default final state) to measure the static state, not an animation frame. **Fails on serious or critical violations**; moderate/minor are listed in the log. `/en/books` is audited twice: the destination after the jump (`/en/#books`, both themes) and the minimal page itself (only the meta refresh and jump script are removed so it does not navigate). The analytics notice exists only in the production build, so it is audited on pushes to master, not on PRs. Requests to Google Analytics domains are aborted, so audits never send real hits.
- **Mobile journey fit and touch scrolling**: `tests/a11y/journey-mobile.spec.ts` uses real Chromium touch events at 390×844 with animations enabled, on EN/ES. Swiping the Profile card must advance page scroll both when its contents fit and at an inner-scroll boundary; scroll chaining must not be trapped by `overscroll-behavior: contain`. The English height-budget checks at 375×812 and 390×844 inspect each of the six cards at its reading point: pinned layout, no clipping/inner overflow, and ≥44px link targets. Profile illustration stays visible; labels return with animations off or static fallback. Short-phone axe checks cover Profile/Education in dark/light.
- **Responsive journey scrolling**: `tests/a11y/journey-scroll.spec.ts` uses the four-resolution English CI matrix: 375×812, 390×844, 768×1024, and 1920×1080. Wheel gestures over every card must advance window scroll and measured journey progress; mobile/tablet also use real touch swipes. A separate scrub verifies hologram frame changes (resting cards intentionally hold their pose). Animations-off checks retain all six cards and normal document scrolling. These run in the same `a11y` CI job without another build. For broader local verification, also inspect 360×640, 360×800, 375×667, 390×700, and 412×915 in EN/ES, including labels hidden only in fitting animated journeys at ≤700px height and restored in static/animations-off views.
- **Lighthouse (job `lighthouse`)**: `@lhci/cli` (exact devDependency in `package-lock`, installed with `npm ci --ignore-scripts`) with `lighthouserc.cjs`: 3 runs (median) on `/en/`, `/es/`, `/en/visits`, and `/en/privacy`, default mobile preset. Thresholds: performance ≥ 0.85, accessibility ≥ 0.95, best practices ≥ 0.9, SEO ≥ 0.95. `/en/books` is excluded: client redirect to `/en/`, which is already measured. No external service: reports in `lighthouse-report/` (`upload.target = filesystem`). Google Analytics domains are blocked (`blockedUrlPatterns`; the resulting `ERR_BLOCKED_BY_CLIENT.Inspector` is ignored by `errors-in-console`), so audits send no hits and do not count gtag's download in performance. Lighthouse waits for the server's ready line (`SERVER_READY_MARKER`, «Serving …» in `scripts/serve-static.mjs`); a unit test fails if `startServerReadyPattern` stops matching it. Two profiles, by `/geo` country:
  - `npm run lighthouse` (always): visit from outside the notice zone (`US`). **All thresholds fail CI.**
  - `npm run lighthouse:consent` (only on push to master, the only build with Google Analytics and notice): first visit from the EU (`ES`), with the notice on screen. Accessibility, best practices, and SEO fail CI; **performance only warns** (reports in `lighthouse-report-consent/`, same artifact).
- **Why performance with the notice does not block** (November 2026 decision, after the first push to master with Lighthouse): the notice is `client-only` and appears when the app has hydrated and `/geo` has responded (hidden until country is known, so it is not shown to those who should not see it). As the largest text on screen, it becomes LCP even though content is already painted: locally, with the production build, LCP 4.5–4.6 s and performance 0.81–0.83 on `/en/`, `/es/`, and `/en/visits` (without notice: LCP 0.9–1.0 s, performance 0.96–0.99). Improving it requires redesigning the notice (prerender it visible and hide later outside the EU, which would make it flash for everyone else), so it stays measured and visible but does not block deploy until decided. Other categories are still required with the notice: for example, its privacy link has descriptive text («Detalles de privacidad» / "Privacy details") because «Más información» failed the SEO `link-text` audit.
- **Coverage (in `verify`)**: `npm run coverage` (`@vitest/coverage-v8`, same version as vitest) replaces `npm run test`. **Blocking threshold: 80%** on lines, statements, functions, and branches (`coverage.thresholds` in `vitest.config.ts`). Counts all own TS/JS from `app/composables`, `app/utils`, `lib/`, `data/`, `server/`, `netlify/`, and `scripts/`, whether tests load it or not. Excluded as non-app code: tests, config (`*.config.ts`, `app/app.config.ts`), generated (`.nuxt/`, `.output/`), and `node_modules/`. `.vue` files (components and pages) are not included yet; axe and Lighthouse cover them. The table appears in the job summary (`scripts/coverage-summary.mjs` → `$GITHUB_STEP_SUMMARY`).
- **Two Vitest projects**: `unit` (`tests/unit/`, Node: pure logic, data, Netlify functions, Nitro route, and scripts) and `nuxt` (`tests/nuxt/`, Nuxt environment from `@nuxt/test-utils` with happy-dom: composables with auto-imports, i18n, and lifecycle). `scripts/` modules export their logic and only act when run with `node` (`scripts/isDirectRun.mjs`); PDF separates CLI (`generate.ts`) from logic (`render.ts`).
- **Viewing reports**: GitHub → Actions → run → *Summary* (coverage table) and, below, *Artifacts*: `coverage` (open `index.html`), `lighthouse-report` (one HTML per run and `manifest.json` with scores; on push to master also `lighthouse-report-consent/`) and `a11y-report` (Playwright HTML report). Kept 7 days.
- **Locally**: `npm run generate` then `npm run test:a11y` or `npm run lighthouse` (starts the server on `127.0.0.1:4173`; needs Google Chrome). To reproduce a push to master: `CONTEXT=production npm run generate` then `npm run lighthouse` and `npm run lighthouse:consent`. Reports: `playwright-report/` (`npx playwright show-report`), `lighthouse-report/`, and `coverage/index.html`.
